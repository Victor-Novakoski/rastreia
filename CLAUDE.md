# Rastreia

Rastreio de entregas em tempo real para transportadoras: painel da transportadora, app do motorista (rota do dia) e página pública de rastreio para quem recebe. Projeto de portfólio, multi-tenant, sem serviço pago.

**Stack:** Go (chi, pgx + sqlc, golang-migrate), PostgreSQL, Redis, RabbitMQ, WebSocket, Web Push · front em `web/` com Vite, React, TypeScript, Tailwind, TanStack Query.

## Comandos

```bash
docker compose up    # tudo com hot reload: api/worker (air), front :5173, RabbitMQ :15672, Mailpit :8025
make test            # go test -race, com integração (precisa de Docker)
make test-short      # só os unitários
make lint            # golangci-lint v2.14.0, mesma config da CI
make sqlc            # regenera internal/store a partir das queries
cd web && npm test && npm run lint && npm run typecheck
```

Armadilhas do ambiente local:
- Porta 5432 ocupada na máquina: `DB_PORT=5433` no `.env` (e a mesma porta na `DATABASE_URL` para rodar o air fora do Docker).
- air no container e na máquina usam a porta 8080: um de cada vez.
- O `.air.toml` usa `tmp/` e `build.bin` porque o air antigo (v1.51) não aceitava `tmp_dir` absoluto nem `build.entrypoint`; o aviso "build.bin is deprecated" é esperado.
- Imagens de dev e de produção têm nomes diferentes (`rastreia-api-dev` e `rastreia-api`) para um `up` sem `--build` não pegar a errada.

## Como se orientar

Leia [docs/INDEX.md](docs/INDEX.md) e abra só o que a tarefa pede. Cada pasta com regras próprias tem o seu `CLAUDE.md`.

## Regras gerais

- **Escopo:** funcionalidade nova precisa caber no [PRD](docs/PRD.md) e ter issue. Uma tarefa por vez; melhoria que aparecer no caminho vira issue nova. Nada de dependência ou camada "para o futuro".
- **Idioma:** docs, textos da interface e commits em português. Identificadores em inglês; comentários em inglês no Go e em português no front.
- **API:** convenções de [DESIGN.md](docs/DESIGN.md) (erro, paginação, snake_case). Rota nova ou alterada atualiza `api/openapi.yaml` no mesmo commit (`TestOpenAPI` confere).
- **Testes:** regra nova tem teste no service; rota nova, teste do handler; bug corrigido ganha teste que falhava antes.
- **Pronto** = sobe com `docker compose up`, tem testes, passa no lint, checklist de segurança revisado, OpenAPI e docs em dia, issue fechada.

## Segurança: checklist de toda mudança

Detalhes em [docs/SECURITY.md](docs/SECURITY.md).

- Entrada validada no back-end, com tamanho máximo, mesmo que o front valide.
- Rota nova com autenticação e papel explícitos; rota pública é exceção justificada.
- Recurso buscado por id confere se é de quem pede (IDOR).
- Resposta sem hash, token, dado pessoal desnecessário ou detalhe interno de erro.
- Nenhum segredo no código, log ou commit; variável nova vai para `.env.example` com placeholder.
- Dependência nova é necessária, mantida e passa no `govulncheck`.

## Git

- `main` é o publicado; `develop` junta o próximo release. Ninguém faz push direto nas duas: tudo por PR para a `develop`.
- Branch a partir da `develop` com o tipo do commit (`feat/...`, `fix/...`, `docs/...`). Atualizar com `git pull --rebase origin develop`.
- O Victor faz os merges: squash na `develop`; `develop` → `main` com merge commit. A branch é apagada depois do merge.
- Conventional Commits em português e minúsculo: `tipo(escopo opcional): assunto`. O título do PR segue o mesmo formato (a CI confere, porque vira o commit do squash).
- Commits com a identidade do Victor, sem linha de atribuição de IA. A integração do GitHub põe sozinha um rodapé "Generated by Claude Code" na descrição do PR (e repõe ao editar): remover; se voltar, só à mão.
- A CI roda em PR e em push na `develop` e na `main`.
- Nunca commitar `.env`, binários ou arquivo gerado fora do sqlc.

## Na nuvem (sessão sem Docker)

- Não há Docker: testes de integração seguem [internal/testdb/CLAUDE.md](internal/testdb/CLAUDE.md).
- sqlc e golangci-lint v2.14.0 instalam com `go install` (gcc presente).
- Nunca `pkill -f` com um padrão que aparece no próprio comando (mata o shell): use `pkill -x api` ou `kill <pid>`. Mate os processos api/worker que sobrarem depois dos testes.

## Glossário

- **Transportadora (carrier):** o tenant; papel `carrier` (antes `admin`).
- **Motorista (driver):** só vê as próprias entregas.
- **Destinatário:** sem conta; acompanha pelo código de rastreio.
- **Evento:** registro de mudança de status de uma entrega.

## Manutenção dos docs

- Antes de uma tarefa, leia docs/INDEX.md e abra só o que ela pede.
- Ao terminar, se aprendeu algo não documentado que faria falta, registre no CLAUDE.md do módulo.
- Doc passou de ~150 linhas? Divida por subtema e atualize o INDEX.
- Decisão de arquitetura nova → arquivo novo em docs/decisoes/.
- Se o código contradiz o doc, o código vale: corrija o doc e avise.
